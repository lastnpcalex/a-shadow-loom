# Search Space policy proof

Lean 4.33.1 proves the pure policy predicates used by `search_space/policy.py`:

- Reads require an active scope, its assigned workspace and the same source.
- Excluded workspaces cannot be read; sensitive workspaces require local routing.
- Ancestry requires matching conversation, thread, workspace and parent identity,
  and rejects revisiting a message.
- The allowlist contains exactly the three history retrieval tools.
- Cloud routing requires a nonempty, classified selection with no excluded or
  sensitive workspace. Exclusion always denies routing.

`cases.json` is generated by the proved definitions: all 48 read combinations,
32 ancestry combinations, 16 routing combinations and ten named tool examples.
The tool theorem itself quantifies over arbitrary strings, beyond those examples.
`tests/test_search_policy.py` checks Python conformance with the generated oracle.

From this directory:

```powershell
lake build --wfail
lake exe search_fixtures cases.json
git diff --exit-code -- cases.json
```

From the repository root:

```powershell
C:\Python314\python.exe -m pytest tests/test_search_policy.py
```

The proofs assume the boolean evidence passed to these predicates is correct.
Capability issuance/revocation, SQLite transactions, live assignment checks,
HTTP/MCP transport and ancestry traversal are validated by executable tests;
they are not mechanically proved here. No proof establishes model relevance,
model instruction compliance or whole-program confidentiality. Search model
actions remain constrained by the runtime allowlist even if the model ignores
its instructions. No `sorry` or axioms are used.

The MCP tests start the actual stdio server and call all three tools through
isolated HTTP/HTTPS APIs backed by temporary SQLite databases. Eleven transport
configurations cover Claude Code, local CC, Dream CC, OpenRouter, Umans, Codex,
Antigravity, Goose, local Goose, Dream Goose and Codex over HTTPS. Five CC launch

provider authentication were not exercised. The embedding probe uses the real
installed model on synthetic text only. Browser acceptance verifies follow-ups,
restoration after reload, saved searches, and exact conversation/branch links.

The two broader failures were
`test_goose_generation_hands_explicit_openrouter_selector_to_claude_code` and
`test_goose_generation_passes_selected_effort`. Both asserted conversation-level
setting persistence in fixtures that enable parallel agents, where production
preserves per-run selection instead. Re-executing Git HEAD versions of
`server.py` and `database.py` in an isolated process reproduced both failures.
No change to that unrelated settings behavior was included.

`pip check` reported inconsistent shared NumPy metadata and a torch/torchaudio
version mismatch. Metadata selected NumPy 2.2.6 although the actual imported
NumPy was 2.5.3; both distribution metadata directories existed. Pandas imports,
Series arithmetic, OpenCV resize/color conversion, Pillow image resizing and
MoviePy import passed. This was not a clean dependency-environment attestation;
unrelated package repair was left outside the initial search change. The later
repair is documented in [PYTHON_ENVIRONMENT.md](../../PYTHON_ENVIRONMENT.md).

The main and admin Loom servers were neither stopped nor restarted. The live
conversation database was not used by these tests. Activation of new routes,
revision triggers and per-turn MCP configuration awaits a human main-server
reload; admin reload is unnecessary for this change.
